# GIS Wetland Degradation & Depletion Engine — User Guide

This guide describes how to configure, run, and interpret the GIS Wetland Degradation & Depletion Engine V1.

---

## 1. Prerequisites and Installation

### System Requirements
- Operating System: Windows 10/11 or Linux.
- Python: version 3.8 to 3.14.
- GPU (Optional): NVIDIA GPU with CUDA drivers installed (for accelerated ONNX model inference). The engine will automatically and observably fall back to CPU if GPU execution providers are unavailable.

### Dependencies
The engine relies on standard spatial and scientific computing libraries:
- `numpy`: Numerical operations and matrix math.
- `rasterio`: Spatial raster read/write and CRS transformations.
- `onnxruntime` or `onnxruntime-gpu`: Deep learning model execution.
- `scipy`: Patch-filtering and component labeling.
- `shapefile` (PyShp): Shapefile boundary ingestion.

Install the required python environment packages:
```bash
pip install numpy rasterio onnxruntime scipy pyshp pytest pytest-cov
```

## 2. Command Line Interface (CLI) Usage

The CLI is the easiest way to invoke a production run from the terminal or scripting environments.

### Command Syntax
```bash
python scripts/run_analysis.py \
    --t1 <T1_SCENE_DIR> \
    --t2 <T2_SCENE_DIR> \
    --t1-date <YYYY-MM-DD> \
    --t2-date <YYYY-MM-DD> \
    --config configs/config.json \
    --model models/best_finetuned_model.onnx \
    --output outputs/runs \
    [--wetland-boundary <PATH_TO_VECTOR>] \
    [--run-id <CUSTOM_RUN_ID>] \
    [--log-level INFO] \
    [--json-summary]
```

### Argument Reference
- `--t1` (Required): Path to the $T_1$ (baseline) Sentinel-2 scene directory containing the band files (e.g. green, red, rededge, nir).
- `--t2` (Required): Path to the $T_2$ (target) Sentinel-2 scene directory.
- `--t1-date` (Required): Date of the T1 acquisition in `YYYY-MM-DD` format.
- `--t2-date` (Required): Date of the T2 acquisition in `YYYY-MM-DD` format. Must be later than `--t1-date`.
- `--config` (Required): Path to the `config.json` configuration file.
- `--model` (Required): Path to the trained 5-channel ONNX classification model.
- `--output` (Required): Base output directory. The engine automatically creates a unique subdirectory named `<run_id>/` inside this path.
- `--wetland-boundary` (Optional): Path to a wetland shapefile (`.shp`) or GeoJSON (`.geojson`) vector boundary. If provided, restricted wetland metrics are calculated.
- `--run-id` (Optional): Overrides the default autogenerated run ID.
- `--log-level` (Optional): Verbosity level (`DEBUG`, `INFO`, `WARNING`, `ERROR`).
- `--json-summary` (Optional): If set, a compact JSON summary is printed to stdout upon completion, suitable for shell pipelines.

### Example Run
```bash
python scripts/run_analysis.py \
    --t1 data/2023-08-14 \
    --t2 data/2023-08-28 \
    --t1-date 2023-08-14 \
    --t2-date 2023-08-28 \
    --config configs/config.json \
    --model models/best_finetuned_model.onnx \
    --output outputs/runs \
    --json-summary
```

### CLI Exit Codes
The CLI returns structured exit codes matching standard operating procedure:
- `0` — Success or Warning (run completed, outputs written).
- `1` — Input validation error (missing band, invalid date order).
- `2` — Configuration error (missing key, malformed JSON).
- `3` — Alignment error (no spatial overlap between scenes).
- `4` — Inference error (ONNX execution failure).
- `5` — Output error (permission denied, drive full).
- `6` — Unexpected internal error.

## 3. Python API Usage

To invoke the engine programmatically inside custom Python scripts or web services, use the public API.

### Import and Invocation
```python
from pathlib import Path
from src.gis_engine.api.service import analyze_wetland

# Invoke analysis run
result = analyze_wetland(
    t1_scene=Path("data/2023-08-14"),
    t2_scene=Path("data/2023-08-28"),
    t1_date="2023-08-14",
    t2_date="2023-08-28",
    config_path=Path("configs/config.json"),
    model_path=Path("models/best_finetuned_model.onnx"),
    output_dir=Path("outputs/runs"),
    wetland_boundary=Path("data/wetland_boundary.geojson"),
    log_level="INFO"
)

# Inspect the result object
print(f"Run ID: {result.run_id}")
print(f"Status: {result.status}") # "SUCCESS", "WARNING", or "FAILED"
print(f"Output Directory: {result.output_directory}")

if result.status == "FAILED":
    print("Errors occurred:")
    for err in result.errors:
        print(f" - {err}")
else:
    print("Metrics calculated:")
    print(f"Normalized Degradation Ratio: {result.metrics.get('normalized_degradation_ratio')}")
    print("Written files:")
    for key, path in result.outputs.items():
         print(f" - {key}: {path}")
```

## 4. Understanding Output Packages

Every successful run generates an isolated, self-contained output directory structure:

- `analysis_result.json`: Flat dictionary containing all scalar parameters, metrics, QA flags, and timing statistics.
- `config_used.json`: Verbatim snapshot copy of the `config.json` used for this run.
- `metadata.json`: Provenance metadata recording runtime environments, git hashes, and input file hashes.
- `manifest.json`: Output file inventory with individual file sizes and SHA-256 hashes to guarantee data integrity.
- `reports/analysis_report.md`: Complete Markdown report detailing the findings.
- `logs/analysis.log`: Detailed execution log with prepended step markers.
- `vegetation/`: Contains categorical GeoTIFF classification maps (`t1_health.tif`, `t2_health.tif`) colored according to the configuration colormap.
- `change/`: Contains the transition map and continuous Change Vector Analysis rasters.
- `degradation/`: Contains final degradation and recovery maps.
- `wetland/`: Contains the rasterized wetland mask.
- `hydrology/`: Contains NDWI water state and change rasters.
- `fusion/`: Contains multi-evidence fusion maps (`evidence_fusion.tif`).
- `metrics/`: Contains transition matrices and area metric CSVs.

## 5. Conservative Scientific Interpretation

Users must interpret the results in accordance with conservative scientific principles:
- **Evidence vs Depletion**: The engine identifies *vegetation degradation evidence* and *surface-water change evidence*. The classification maps are derived from optical imagery and should **never** be described as proving physical wetland depletion on their own.
- **Physical Depletion Assessment**: By default, the assessment status remains `NOT_ASSESSED`. A supported assessment status requires integrating independent ground-truth data (such as soil core samples or groundwater gauges) as specified in `docs/configuration.md`.
